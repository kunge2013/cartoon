# 02 - 功能清单与流程设计（先干什么，再干什么）

> 本章回答两个问题：
> 1. 雪漫画有哪些功能（完整清单，逆向取证）；
> 2. 复刻时**先做什么、后做什么**（分期路线，每期有明确前置依赖、产出与验收标准）。

## 二、实施路线：先干什么，再干什么

> 排序原则：
> 1. **地基先行**：提示词管理 + 拼装引擎是所有 AI 功能的地基，最先做（用户明确要求着重）；
> 2. **主线最短路径优先**：先打通"文本->分镜->图片"最小闭环，再补视频/配音/放大等支线；
> 3. **每个 Phase 结束都有可验收的可用功能**，不允许出现"半成品堆积"。

### 总览图

```mermaid
flowchart LR
    P0[Phase 0 环境与骨架] --> P1[Phase 1 ★提示词管理+拼装引擎]
    P1 --> P2[Phase 2 小说中心: 导入/清洗]
    P2 --> P3[Phase 3 角色中心: AI角色推导]
    P3 --> P4[Phase 4 项目/分镜: AI拆分镜+编辑]
    P4 --> P5[Phase 5 图片提示词推导]
    P5 --> P6[Phase 6 图片生成与候选图]
    P6 --> P7[Phase 7 导出长图]
    P7 --> P8[Phase 8 画风库/批量调度]
    P8 --> P9[Phase 9 视频模式+TTS+合成]
    P9 --> P10[Phase 10 高清放大/一键漫剧/其余]
```

### Phase 0：环境与工程骨架（0.5 天）

- **先做**：conda env `catong_gen`（Python 3.11，**已创建**）；backend FastAPI 骨架 + SQLite + Alembic；frontend Vite 脚手架；`scripts/dev.bat`。
- **产出**：`/api/health` 可访问；前端空白页可打开；迁移可执行。
- **验收**：`conda activate catong_gen && uvicorn app.main:app` 启动无错。

### Phase 1：★ 提示词管理模块 + 拼装引擎（2~3 天，重点）

- **前置**：Phase 0。
- **做什么**（按顺序）：
  1. 提示词五件套数据表：`prompts`（库）、`prompt_snippets`（片段）、`prompt_templates`（模板）、`prompt_presets`(预设)、`prompt_render_logs`（渲染历史）；
  2. 提示词库 CRUD + 分类管理 + 导入/导出（JSON）；
  3. **迁移源库 13 条内置提示词为种子数据**（scripts/seeds，含小说视频提示词指令/获取人物形象/角色三视图/人物形象视频/图片推导词默认前后缀/视频推导词默认前后缀/分镜短长文本版/一键对话/文案同义改写/VIP智能角色推导）；
  4. 拼装引擎：分段模型（前缀/风格/上下文/指令/后缀/负面）、Jinja2 变量渲染、覆盖链（内置->预设->项目->分镜）、dry-run 预览 API；
  5. 前端页面：提示词库（表格+抽屉编辑+分类筛选）、拼装调试台（选阶段->填变量->实时预览分段结果）。
- **产出**：提示词五件套全部可用；`POST /api/assemble/preview` 返回分段高亮结果。
- **验收**：导入源库提示词后可搜索、编辑、分类；拼装调试台用样例上下文渲染出三段式 image_prompt 雏形。

### Phase 2：小说中心（1 天）

- **前置**：Phase 1（清洗规则不依赖 LLM，但"AI 文本处理"依赖提示词体系）。
- **做什么**：TXT 导入/粘贴、名称提取、文本清洗（格式/连载号/标点，规则引擎不调 LLM）、多标签页正文（custom_tabs 结构对齐源库）、原文多阶段字段建好（character_text 等先占位）。
- **验收**：导入一章网文 -> 一键清洗 -> 差异对比查看。

### Phase 3：角色中心（1~2 天）

- **前置**：Phase 2 + LLM 供应商配置。
- **做什么**：角色标签字典（category_tags 种子：类型/时空）；AI 角色推导（用迁移的"VIP智能角色推导"预设，LLM 输出 JSON 角色列表 -> 入库 roles）；角色卡编辑（视觉描述/别名）；角色删除/排序。
- **验收**：一章小说 -> 一键推导出角色卡（含年龄段拆分），可编辑。

### Phase 4：项目与分镜（2 天）

- **前置**：Phase 2/3。
- **做什么**：项目管理（mode=manga 先行）；分镜拆分（"分镜提示词-短/长文本版"预设二选一）；scripts 表 CRUD + 分镜编辑器（内容/备注/排序/生成开关）；项目摘要 AI 生成。
- **验收**：小说 -> 拆分出编号分镜列表 -> 可编辑排序。

### Phase 5：图片提示词推导（2 天，拼装引擎落地）

- **前置**：Phase 1 拼装引擎 + Phase 4。
- **做什么**：图片推导预设（对标 plot_manga_fusion_bw：画风总述+版式逻辑+负面后缀三段式输出指令）；上下文注入（角色卡 content、前情分镜、项目摘要、画风前缀、项目前后缀）；逐镜推导 image_prompt；推导原始日志落 prompt_render_logs。
- **验收**：某分镜 -> 推导出三段式 image_prompt，与源库 scripts_list.image_prompt 结构一致（画风总述/版式详解/固定负面后缀）。

### Phase 6：图片生成（2 天）

- **做什么**：图像供应商抽象 + OpenAI 兼容/GRSai 适配器；image_tasks 状态机（pending/running/done/failed）；单镜生成 + 批量生成（并发上限取 settings）；候选图与主图选择；文件落 `Output/<project>/<episode>/image/`。
- **验收**：选一镜 -> 生成 1~4 张候选 -> 选主图 -> 图片文件落盘且路径回写。

### Phase 7：导出（1 天）

- **做什么**：长图拼接（Pillow 垂直拼接 + 页码/标题可选）、ZIP 打包；导出参数（对标 manga_export_style4_prefs 的精简版）。
- **验收**：一个项目导出为一张竖排长图。

### Phase 8：画风库与批量调度（2 天）

- **做什么**：画风库表 + 159 条种子（从源 styles_mapping.json 迁移，预览图复制）；画风绑定项目（参考图/前缀注入）；批量队列 UI + 失败重试 + 模型链降级雏形。

### Phase 9：视频模式与配音（3~5 天，后期）

- camera 模式分镜、文生视频（首尾帧）、TTS 配音工程、FFmpeg 合成、字幕（srt）。

### Phase 10：高级与收尾（后期）

- 高清放大（Real-ESRGAN 集成）、剪映草稿导出（pyJianYingDraft）、一键漫剧编排、项目备份、平台抓取（番茄/知乎）。

## 三、依赖关系（为什么是这个顺序）

```
提示词管理(1) ──┬──> 角色推导(3) ──┬──> 图片提示词推导(5) ──> 图片生成(6) ──> 导出(7)
               ├──> 文本AI处理(2) ─┤
               └──> 分镜拆分(4) ───┘
```

- 角色推导/分镜拆分/文案改写**都只是"提示词库里的不同模板 + 不同上下文"**，所以 Phase 1 完成后，Phase 2~5 的 AI 部分都是"填模板、组上下文、调 LLM"的重复动作，工期短、风险低。
- 图片生成(6) 只依赖推导产物(5) 与供应商配置，不依赖导出。
- 视频域(9) 整体后置，因其依赖图片域稳定产出（首帧）。

## 四、里程碑与最小可用版本（MVP）

**MVP = Phase 0~7**：在浏览器里完成"导入小说 -> 清洗 -> 角色推导 -> 分镜拆分 -> 图片提示词推导 -> 生成候选图 -> 选主图 -> 导出长图"全流程。预计 8~11 个工作日。
