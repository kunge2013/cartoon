# 06 - 提示词拼装引擎设计（★ 重点模块：提示词怎么拼、怎么拆）

> 目标：把"一条提示词是怎么被拼出来的"从业务代码里彻底剥离，变成**显式、可预览、可回放**的流水线。用户明确要求"便于后期拆解提示词拼装"——本章即拆解方案。

## 一、两类拼装场景（先分清）

复刻雪漫画时必须区分两种"拼提示词"：

| 场景 | 输入 | 输出 | 例子 |
|------|------|------|------|
| **S1 直接拼装（Deterministic）** | 已有素材（片段/前后缀/角色卡文本） | 最终提示词，**不经过 LLM** | 图片生成请求 = 项目前缀 + image_prompt + 负面片段；角色三视图 = 角色卡 + portrait_render 片段 + 画风前缀 |
| **S2 推导指令组装（LLM Derive）** | 预设模板 + 上下文变量 | **喂给 LLM 的指令**；LLM 的回答才是业务产物 | 图片提示词推导（三段式）、分镜拆分、角色推导、文案改写 |

引擎对两类场景提供**同一个管线**，只是终点不同：S1 的 rendered 即成品；S2 的 rendered 是 LLM 输入，LLM 输出再由业务侧解析落库。

```
S1: preset+context ─► [拼装引擎] ─► rendered ─► 图像API
S2: preset+context ─► [拼装引擎] ─► rendered ─► LLM ─► 解析 ─► scripts.image_prompt / roles / 分镜列表
```

## 二、分段模型（Segment Model）—— 拼装的原子单位

任何一次拼装 = 有序的分段列表。每个分段有明确的 `key`、来源与渲染规则：

| key | 来源 | 说明 | 源系统实证 |
|-----|------|------|-----------|
| `project_affix_prefix` | projects.img_prompt_prefix / vid_prompt_prefix | 项目级前缀，最外层 | projects 表四列 |
| `style_prefix` | 片段(tag=style_prefix) 或画风库注入 | 画风定性句 | prompts#5"顶级韩漫风格…"；asset_art_style_json |
| `system` | 模板主体固定开头（角色设定/任务说明） | 指令的"人设段" | 每条源提示词的 `# Role` 部分 |
| `instruction` | 模板主体可变部分（逻辑约束/输出格式） | 指令的"任务段" | `# Task / # Logic Constraints` |
| `context` | 业务注入（角色卡/前情分镜/项目摘要/本镜内容） | 变量渲染结果 | context_generator 模块职责 |
| `custom_slots` | preset.slots_json（custom_1..custom_6） | 用户自定义补充指令 | derive_custom_slot_label/instruction_1..6 |
| `project_affix_suffix` | projects.img_prompt_suffix / vid_prompt_suffix | 项目级后缀 | projects 表 |
| `negative` | 片段(tag=negative)，preset 附着 | 强制负面约束，**永远最后** | "禁止：…腾讯动漫 17173 等其他机构水印！" |

**默认顺序**（可被模板覆盖）：

```
project_affix_prefix → style_prefix → system → instruction → context → custom_slots → project_affix_suffix → negative
```

> 拆解价值：调风格只动 `style_prefix` 片段；防水印只动 `negative` 片段；个性化只动 `custom_slots`——互不牵连。

## 三、上下文（AssemblyContext）

引擎输入统一为 `AssemblyContext`（纯 dict），由业务服务负责收集：

```python
ctx = AssemblyContext(
    stage="image_derive",                # 业务阶段
    preset_id="plot_manga_fusion_bw",    # 预设（缺省取该 stage 激活预设）
    variables={                          # 全部可用变量
        "style_prefix": "...",
        "project_summary": "...",
        "roles": [{"name": "纪澄青年", "content": "..."}],
        "prev_shots": [...],
        "shot_content": "...",
        "novel_text": "...",
    },
    target=("scripts", 10023),           # 落点（写 render_logs 用）
)
```

### 3.1 每阶段的变量契约（Stage Contract）

| stage | 必填变量 | 可选变量 | 输出解析 |
|-------|---------|---------|---------|
| role_derive | novel_text | era_hint, extra_roles | JSON `[{name, content}]`，容错降级为行解析 |
| storyboard_short / _long | novel_text | continue_from（续拆锚点） | 编号列表 `1. xxx`，按行解析 |
| dialogue_split | novel_text | - | 【旁白】/【角色名对白】行解析 |
| rewrite | novel_text | - | 纯文本整段 |
| image_derive | shot_content, style_prefix | roles, prev_shots, project_summary, project_img_prefix/suffix, custom_1..6, negative_suffix | 三段式文本（\n\n 分割） |
| video_derive | shot_content | roles, prev_shots | 镜头表（markdown 表格） |
| role_portrait | role_content | portrait_render(片段), art_style_name | 纯文本（直接做图像请求） |
| summary | novel_text | max_words | 纯文本 |

> 契约即文档：`GET /api/assemble/stages` 返回上表，前端调试台据此生成表单。

## 四、渲染管线（Pipeline）

```
AssemblyContext
   │
   ▼
[1] 预设解析      取 preset -> template（版本固定）；缺省 preset = stage 激活预设
   │
   ▼
[2] 变量合并      内置默认值 <- 片段注入(style_prefix/negative) <- preset.slots <- ctx.variables
   │               （优先级从低到高，右侧覆盖左侧）
   ▼
[3] 模板渲染      Jinja2 StrictUndefined（未声明变量直接报错，防止静默漏拼）
   │
   ▼
[4] 分段切分      模板内用注释标记分段边界，渲染后按标记切出 segments
   │               标记语法（渲染时剥离）：<!--#seg:key-->
   ▼
[5] 后处理        去多余空行；首尾空白；全角/半角逗号规整（可配置）
   │
   ▼
[6] 结果          { segments: [...], rendered: "..." }  +  落 prompt_render_logs
```

### 4.1 模板中的分段标记（示例：image_derive 模板）

```jinja
<!--#seg:system-->
你是一位顶级条漫画师，擅长把小说分镜推导为多格条漫图片提示词。

<!--#seg:instruction-->
严格输出三段（空行分隔）：
第一段 画风与多格场景总述，以"{{ style_prefix }}"开头；
第二段 版式逻辑详解（格子比例/阅读动线/色彩规范/字框样式 白底黑边黑字#1a1a1a）；
第三段 逐字输出负面句："{{ negative_suffix }}"。

<!--#seg:context-->
【项目摘要】{{ project_summary }}
【角色卡】
{% for r in roles %}{{ r.name }}：{{ r.content }}
{% endfor %}【前情分镜】
{% for s in prev_shots %}第{{ s.order }}镜：{{ s.content }}
{% endfor %}【本镜内容】{{ shot_content }}

<!--#seg:custom_slots-->
{% if custom_1 %}{{ custom_1 }}{% endif %}

<!--#seg:negative-->
{{ negative_suffix }}
```

### 4.2 覆盖链（谁覆盖谁）

```
内置默认（代码）
  < 片段库（style_prefix / negative …）
    < 预设槽位（preset.slots_json）
      < 项目级（projects.img_prompt_prefix/suffix）
        < 单镜级（scripts.notes 指令、编辑过的 image_prompt 不再被自动覆盖）
```

- 自动推导**只写空 image_prompt**；用户手工编辑过的镜 `is_main_locked=1` 语义之外再加 `prompt_touched=1`（extra），批量重推导跳过；
- 这条链保证"全局改风格"与"单镜微调"共存（源应用痛点：全局重推导会覆盖手改）。

## 五、引擎代码结构（backend/app/prompt_engine/）

```python
# context.py
@dataclass
class AssemblyContext:
    stage: str
    preset_id: str | None = None
    variables: dict = field(default_factory=dict)
    target: tuple[str, int] | None = None

# segments.py
SEGMENT_ORDER = ["project_affix_prefix","style_prefix","system","instruction",
                 "context","custom_slots","project_affix_suffix","negative"]

def split_segments(rendered: str) -> list[Segment]  # 按 <!--#seg:key--> 切分并剥离标记

# renderer.py
class Renderer:
    def render(template_body: str, variables: dict) -> str   # Jinja2 StrictUndefined
    def list_variables(template_body: str) -> list[str]      # 正则抽取 {{ var }} / {% for x in xs %}

# assembler.py
class Assembler:
    def assemble(self, ctx: AssemblyContext) -> AssemblyResult
    # 1 取激活预设 2 合并变量(默认+片段+槽位+ctx) 3 渲染 4 切分段 5 后处理 6 落日志

# contracts.py
STAGE_CONTRACTS: dict[str, StageContract]  # §3.1 的表，代码化
```

**依赖方向**：`routers/assemble.py` 与 `services/*` 调用 `Assembler`；`Assembler` 不 import 任何业务模型（上下文由调用方备好）——保证引擎可独立单测。

## 六、S1 直接拼装的三个内置配方（非 LLM）

| 配方 | 拼法 | 用途 |
|------|------|------|
| image_request | `project_affix_prefix + scripts.image_prompt + project_affix_suffix + negative片段` | 文生图请求（image_prompt 已是三段式成品） |
| portrait_request | `portrait_ref 前缀(画风) + role.content_word2(或 content + portrait_render 片段)` | 角色三视图/立绘 |
| video_request | `project_vid_prefix + scripts.video_prompt + project_vid_suffix + negative片段` | 文生视频请求 |

配方也是 preset（stage=`image_request` 等，template 即拼接顺序），走同一管线，同一日志。

## 七、调试与可观测性

1. **拼装调试台**（前端 `/assemble`）：选 stage/preset -> 表单填变量（或 JSON 粘贴 / 真实数据填充）-> 分段高亮预览；显示每段来源（片段名/槽位/变量名）。
2. **渲染历史**：`prompt_render_logs` 全量落库；分镜详情页可看"该镜提示词的推导输入快照"。
3. **单测快照**：每个内置模板配固定 context 的渲染快照测试（防模板改动引发静默变化）。
4. **变量缺失即报错**：StrictUndefined + API 返回 422 带缺哪个变量——绝不静默出残缺提示词。

## 八、为后期拆解预留的扩展点

| 扩展点 | 预留设计 | 未来用途 |
|--------|---------|---------|
| 分段增删 | SEGMENT_ORDER + 模板标记天然支持新增 key（如 `lora_tags`、`camera_motion`） | 视频/放大/ControlNet |
| 条件分段 | Jinja2 `{% if %}` 已支持按变量开关分段 | 画风库可选注入 |
| 多模板版本 | prompt_templates.version + preset 锁定 template_id | A/B 测试新旧推导指令 |
| 链式推导 | S2 输出变量可回填 context（如先 summary 后 derive） | 一键漫剧编排 |
| 中间件位 | 管线步骤 [5] 后处理可注册函数（敏感词过滤/长度截断/成本统计） | 合规与成本控制 |
